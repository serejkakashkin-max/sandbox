# Помощник разбора логов для ЗПИ

Локальное Flask-приложение для загрузки логов и подготовки заявки на смежную систему. Первая реализованная методика — анализ ситуации, когда после встречи в АС ФОКУС не сформировалось резюме.

Приложение не использует внешние API и не сохраняет загруженные логи на диск: файлы обрабатываются в памяти текущего запроса.

## Интеграция в Sandbox

В монорепозитории `sandbox` проект хранится целиком в каталоге `CA/` и подключается корневым `wsgi.py` как отдельное WSGI-приложение по адресу `/ca/zpi-assistant/`. Благодаря этому проект остается автономным: его по-прежнему можно запускать отдельно на порту `5055`.

Интерфейс использует стилистическую DNA Oplot из проекта `releases`: те же light/dark visual tokens, `data-theme`/`data-bs-theme`, ключ `localStorage["theme"]` и совместимое переключение темы. При работе внутри Sandbox верхняя панель возвращает пользователя на главную Sandbox и корректно учитывает внешний `SANDBOX_PUBLIC_PREFIX`.

Для изоляции от соседних Flask-приложений session-cookie проекта называется `zpi_session`. В production рекомендуется задать `ZPI_SECRET_KEY` через секреты окружения и включить `ZPI_HTTPS=1`.

## Что умеет первая версия

- принимает одновременно несколько файлов `.txt` и `.xlsx`;
- читает обычный JSON, построчный JSON и выгрузки без внешних фигурных скобок;
- в Excel поддерживает таблицы с колонками `message`, `className`, `serverEventDatetime` и одноколоночные JSON-выгрузки;
- находит отправки `record_focus` из `SvaKafkaProducer`;
- группирует чанки по UUID, проверяет номера частей и `isLastRecord`;
- находит ответы `VOICE360_CHECK_MEETINGS_TRANSCRIPTION` для заданной встречи;
- преобразует время с суффиксом `Z` из UTC в `Europe/Moscow`;
- показывает альтернативные UUID и все диагностические предупреждения;
- формирует готовый для копирования текст ЗПИ.

Дополнительные экспертные ветки:

- если для указанной встречи не найдены записи `SvaKafkaProducer`, сервис сообщает, что чанки отсутствуют и возможна ошибка микрофона; рядом показывается инструкция проверки по табельному номеру и дате встречи в Clickstream;
- если последний ответ VOICE360 равен `true`, сервис рекомендует пользователю перепроверить сформированное резюме и предлагает отдельную кнопку для формирования ЗПИ, если перепроверка не решила проблему.

ID встречи является обязательным входным значением и берётся из исходной заявки пользователя, как предусмотрено экспертной методикой.

## Правило выбора данных

Основным считается UUID с наибольшим числом уникальных чанков. При равенстве выбирается более ранняя группа. Время записи берётся из чанка `part=2`, как указано в предоставленной экспертной методике; если такого чанка нет — из первой записи выбранной группы.

Если найдено несколько ответов VOICE360, в заявку включается самый поздний. Полный список совпадений и правило выбора остаются видимыми в интерфейсе: приложение не скрывает неоднозначность исходных логов.

## Установка и запуск

Требуется Python 3.11 или новее. Рекомендуемый вариант с `uv`:

```powershell
cd C:\zpi
uv sync
uv run python app.py
```

После запуска интерфейс доступен на [http://127.0.0.1:5055](http://127.0.0.1:5055), проверка состояния — на `/health`.

Альтернативный запуск через стандартный `venv`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe app.py
```

Для production-подобного запуска используется встроенный в проект Waitress:

```powershell
.\.venv\Scripts\waitress-serve.exe --listen=127.0.0.1:5055 app:application
```

## Проверка

```powershell
uv sync --extra dev
uv run pytest
```

Тесты покрывают TXT, оба варианта XLSX, группировку UUID, преобразование времени, дедупликацию пересекающихся выгрузок, неполные данные, CSRF и полный POST-запрос Flask.

Контрольный результат на предоставленном примере:

- прочитано 2568 строк из двух файлов;
- основной UUID: `421a38e5-d74d-4626-af7f-c1c2ff073333`, 57 чанков;
- отдельный UUID завершения: `2597562e-d01c-4136-8af0-ce17b9ed3333`, `isLastRecord=true`;
- время записи по методике: `2026-08-03T12:42:30`;
- семь уникальных ответов VOICE360, во всех значение `false`.

## Настройки

Настройки задаются переменными окружения:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `ZPI_HOST` | `127.0.0.1` | Адрес прослушивания |
| `ZPI_PORT` | `5055` | Порт приложения |
| `ZPI_SECRET_KEY` | случайный при запуске | Ключ Flask-сессии; на постоянном сервере нужно задать явно |
| `ZPI_MAX_UPLOAD_BYTES` | 60 МБ | Общий предел HTTP-запроса |
| `ZPI_MAX_FILE_BYTES` | 30 МБ | Предел одного файла |
| `ZPI_MAX_FILES` | 10 | Число файлов за один анализ |
| `ZPI_MAX_XLSX_UNCOMPRESSED_BYTES` | 150 МБ | Предел распакованного XLSX |
| `ZPI_MAX_XLSX_ROWS` | 200000 | Предел строк на листе |
| `ZPI_MAX_XLSX_COLUMNS` | 250 | Предел колонок на листе |
| `ZPI_HTTPS` | выключено | Включает флаг `Secure` у cookie при работе через HTTPS |

## Структура

- `zpi_app/parsers.py` — безопасное чтение и нормализация TXT/XLSX;
- `zpi_app/analyzers/transcription.py` — сценарий отсутствующей транскрибации;
- `zpi_app/web.py` — маршруты, CSRF и обработка формы;
- `zpi_app/templates/` и `zpi_app/static/` — русскоязычный интерфейс;
- `tests/` — модульные и веб-тесты.

Новые экспертные методики добавляются отдельными анализаторами в `zpi_app/analyzers/`, используя общий список `LogRecord`.
