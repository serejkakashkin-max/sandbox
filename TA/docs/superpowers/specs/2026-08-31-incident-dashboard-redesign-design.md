# Спецификация: минималистичный дашборд инцидентов

**Дата:** 31.08.2026  
**Статус:** дизайн утверждён пользователем  
**Родительский документ:** `sandbox/TA/docs/SDD.md`

## Цель

Заменить перегруженную главную страницу на компактный настольный дашборд с таблицей, временными периодами от пятницы до пятницы и отдельной повторной проверкой, сохранив существующий анализатор, ручной AI, протоколы, экспорт, безопасность и карточку инцидента.

- Не добавлять пагинацию.

## Утверждённый экран

Эталонные макеты:

- `final-dashboard-current.png` — текущий период;
- `final-dashboard-repeat.png` — повторная проверка;
- `final-dashboard-search.png` — глобальный поиск.

Макеты находятся в каталоге визуализаций текущей задачи и задают композицию, плотность, порядок блоков и визуальные состояния. Реализация должна использовать существующую дизайн-систему TA и поддерживать обе темы.

## Данные представления

Подготовка главной страницы должна выдавать единый объект представления со следующими логическими частями:

```python
{
    "upload": {
        "filename": str,
        "loaded_at": datetime | None,
    },
    "metrics": {
        "total": int,
        "errors": int,
        "warnings": int,
        "correct": int,
        "skipped": int,
        "repeated": int,
    },
    "navigation": {
        "active_section": str,
        "current_period": PeriodView | None,
        "visible_periods": list[PeriodView],
        "overflow_periods": list[PeriodView],
    },
    "active_status": str | None,
    "rows": list[IncidentRowView],
    "repeat_groups": list[RepeatProtocolGroup],
    "search": {
        "query": str,
        "active": bool,
        "return_url": str,
    },
}
```

Названия Python-типов являются целевыми интерфейсами плана реализации; допустима реализация через dataclass или типизированные словари.

`metrics` всегда относится ко всей загруженной выгрузке, а не только к активному периоду. Должно выполняться `total == errors + warnings + correct + skipped`; `repeated` является пересекающимся дополнительным счётчиком.

## Периоды

### Разбор `Создан`

- Пустое, `NaN` и неразбираемое значение возвращают `None`.
- Дата нормализуется в московскую временную зону для определения дня загрузки и границ.
- Граница недели: пятница 00:00 включительно, следующая пятница 00:00 исключительно.

### Пятничная загрузка

Специальный «Текущий» создаётся только для загрузки, выполненной в пятницу по Москве, и только при наличии хотя бы одного инцидента начиная с 00:00 предыдущей пятницы.

Показываемый конец — максимальный распознанный `Создан` во всём файле. Пользовательское название вкладки остаётся «Текущий».

### Остальные периоды

Все остальные распознанные даты распределяются по пятничным неделям. Сортировка — по началу периода по убыванию.

Инциденты без даты:

- входят в «Все»;
- не входят в «Текущий»;
- доступны как период «Дата не определена» через «Ещё»;
- продолжают проходить все детерминированные проверки.

### Переполнение вкладок

- Горизонтальной прокрутки нет.
- Периоды, которые не помещаются, переходят в «Ещё».
- Активный период всегда видим.
- После выбора периода из «Ещё» кнопка «Ещё» остаётся на месте.

## Повторная проверка

### Отбор протоколов

1. Получить существующие `.txt` из каталога протоколов, от новых к старым.
2. Определить пятничную неделю даты каждого протокола.
3. Для одной недели оставить самый новый файл.
4. Выбрать до пяти уникальных недель.
5. Получить ручные записи `incident_history` для выбранных файлов.
6. Если для старого файла записей нет, разобрать только часть текста до секции «В работе».

Автоматические строки секции «В работе» никогда не создают совпадание повторной проверки.

### Сопоставление

- Сравнение ID регистронезависимое после нормализации в верхний регистр.
- Повторным является любой текущий инцидент, вручную присутствовавший хотя бы в одном из выбранных протоколов.
- WARNING и комментарий не являются обязательным условием совпадения.
- Текущий инцидент выводится только в группе своего самого нового совпадения.
- Все более старые совпадения передаются в строку как `history`.

### Раскрытие

Нажатие на дату старого протокола раскрывает под строкой:

- дату и имя протокола;
- WARNING, если был;
- комментарий, если был;
- ссылку на другие совпадения.

Раскрытие не выполняет новый анализ и не меняет данные.

## Статусные категории

Доступные вкладки и внутренние ключи:

| Ключ | Подпись |
|---|---|
| `errors` | На доработку |
| `warnings` | Замечания |
| `all` | Все |
| `correct` | Корректно |
| `skipped` | Не проверяются |

Профиль `in_work` включается в `skipped`. В строке отображается фактический статус «В работе».

При входе в период выбирается первая непустая вкладка: `errors`, затем `warnings`, затем `all`.

## Автоматический выбор раздела

Если параметр раздела отсутствует или недействителен:

1. открыть `repeat`, если есть совпадения;
2. иначе открыть `current`, если он существует;
3. иначе открыть самый новый недельный период;
4. иначе открыть `all`.

Явно выбранный действительный раздел не должен самопроизвольно переключаться.

## Поиск

Параметр `search`:

- обрезается по краям;
- сравнивается через `casefold()`;
- применяется ко всей загруженной выгрузке;
- проверяет только ID и исполнителя;
- игнорирует активный период и статус при построении результатов;
- не уничтожает параметры предыдущего раздела.

Результаты содержат период и итог проверки. Очистка `search` возвращает к сохранённым в URL параметрам `section`, `period` и `tab`.

## Таблица

Каждая обычная строка содержит:

```text
checkbox | ID | Создан | Исполнитель | Результат | Основное | AI | переход
```

Правила:

- ID и стрелка являются обычными ссылками на карточку;
- нажатие на свободную область строки открывает ту же карточку;
- интерактивные дочерние элементы не запускают переход строки;
- AI запускается только кнопкой AI;
- готовый AI открывает сохранённый отчёт;
- максимум одно основное замечание показывается в таблице;
- полный список проверок остаётся внутри карточки;
- все строки выводятся без пагинации.

## Текущий протокол

- Checkbox выбирает строки для существующего массового добавления.
- При выборе появляется единая панель.
- Панель содержит число выбранных, тег и кнопку добавления.
- Инцидент, уже находящийся в текущем протоколе, имеет отдельную подпись.
- Существующие комментарии и удаление из текущей подборки остаются доступны через компактный просмотр «Протокол · N» и карточку инцидента.

## Компактные действия

Верхняя панель сохраняет:

- загрузку Excel;
- формирование/просмотр текущего протокола;
- экспорт;
- историю протоколов;
- частые технические признаки;
- очистку текущей подборки;
- очистку списка;
- копирование ссылки.

Разрушающие действия остаются POST с CSRF и подтверждением.

## Изменение хронологии

Проверка `CHRONOLOGY_REQUIRED` должна возвращать:

```python
{
    "status": "remark",
    "severity": "warning",
}
```

когда заголовок хронологии отсутствует. Проверки событий, времени и порядка хронологии не смягчаются автоматически.

## Совместимость

- Маршруты карточки, AI, протокола, истории и экспорта сохраняются.
- Существующий AI-кэш остаётся действительным.
- Существующая SQLite-схема не требует разрушительной миграции.
- Старые URL с `tab=remarks` и `tab=test` продолжают нормализоваться.
- Устаревшие параметры фильтров могут безопасно игнорироваться, но не должны вызывать 500.

## Проверка готовности

Результат считается готовым, когда:

1. все существующие тесты проходят;
2. новые тесты периодов, поиска, повторных протоколов и хронологии проходят;
3. контрольный Excel разбивается на ожидаемые пятничные периоды;
4. повторная проверка использует пять уникальных недель и игнорирует «В работе»;
5. ручной AI не запускается при загрузке и навигации;
6. добавление в протокол, формирование протокола, экспорт и очистка работают;
7. светлая и тёмная темы читаемы;
8. главная страница не имеет горизонтальной прокрутки навигации;
9. карточка инцидента и кнопки возврата не регрессируют;
10. изменены только файлы TA.
